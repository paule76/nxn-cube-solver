# D1: 4x4-Modell und Darstellung – Implementation Plan

> **For agentic workers:** Execute task-by-task (executing-plans, inline). `bd` is not available; git history on `feature/cube4-model` is the record. **No merge to `main`** (D1 goes live together with D2).

**Goal:** 4x4 wählbar, eingeben, prüfen, mischen und animiert ansehen (inkl. `Rw`-Zügen); 2x2/3x3 unverändert.

**Architecture:** Engine-Züge bekommen `depth`; `src/puzzles/cube4.js` liest Ecken und Kantenstücke aus den Feldern (Stücke werden aus der Geometrie abgeleitet); Views und App nutzen die bestehenden Schnittstellen.

**Spec:** `docs/superpowers/specs/2026-11-12-cube4-model-design.md`

## Global Constraints
- Ausgelieferte Seite ohne Abhängigkeiten/Build; Texte DE + EN; alle bisherigen Unit- und e2e-Tests grün.
- Notation WCA: `Rw`, `Rw2`, `Rw'`; Zug-Objekt `{ face, turns, depth }`, fehlendes `depth` = 1.
- 4x4: 96 Felder, 16 je Farbe, Schema aus Ecke DBL; Mischen 40 Züge aus 36.

## Ruling (Abweichung von der Spec)
- `edgeMirrored` entfällt: Vertauschte Felder eines Kantenstücks ergeben beim 4x4 genau das Partnerstück derselben Kante; das zeigt sich als `duplicateEdge`. Die 4x4-Meldung dazu enthält den Hinweis „evtl. eine Seite gespiegelt eingegeben“. Kosten, falls falsch: eine weniger präzise Meldung.

### Task 2: 4x4-Modell, Prüfung, Mischen
**Files:** Create `src/puzzles/cube4.js`, `test/cube4.test.js`; Modify `src/puzzles/index.js` (`'4x4'`), `src/i18n.js`, `src/messages.js` (Wing-Positionen), `test/puzzles.test.js`

**Ableitung aus der Geometrie (`createGeometry(4)`):**
- Ecken: für die 8 Ecken des 2x2 (Reihenfolge `CORNER_FACELETS` aus `cube.js`) die Felder mit gleicher Normale an der skalierten Position (×3) suchen → `CORNER_FACELETS4`.
- Kantenstücke: Steine mit genau zwei Koordinaten = ±3 und einer = ±1 (24 Stück). Die zwei Felder eines Stücks werden so geordnet, dass `(n₁ × n₂) · p > 0` (p = Position), damit die Leserichtung bei allen Drehungen erhalten bleibt → `WING_FACELETS[24]`. Position-Namen: Kante (z. B. `UR`) + `1`/`2` (kleinere/größere Koordinate entlang der Kante).
- Stückfarben im gelösten Zustand → `WING_COLORS[24]` (Seitenbuchstaben-Paare); jedes Paar ist eindeutig.
- Mitten: die übrigen 24 Felder → `CENTER_FACELETS`.

**Interfaces:** `toFacelets4(state, scheme = DEFAULT_SCHEME)`, `parse4(facelets) -> {ok, state, scheme} | {ok:false, code, params}`, `isSolved4(state)`, `SOLVED4`; Zustand `{ cp, co, wp, centers }` (`centers`: Seitenbuchstaben der 24 Mittelfelder); Modul `cube4 = { id:'4x4', size:4, moveFaces: alle sechs, solvedFacelets, parse, isSolved, applyMoves (Engine n=4), scramble: rng => randomScramble(40, rng, movesFor(4)) }` (kein `solve`).

**Prüfreihenfolge:** `incomplete` → `colorCount {expected:16}` → Schema aus DBL (D/B/L, Gegenfarben; ungültig → `cornerImpossible` an DBL) → Ecken (`cornerImpossible`/`cornerOrder`) → Kantenstücke (`edgeImpossible`, wenn das Farbpaar zu keiner Kante gehört) → `duplicateCorner` → `duplicateEdge` (4x4-Text mit Spiegel-Hinweis: Schlüssel `error.duplicateEdge4`) → `twistedCorner`. Mitten brauchen keine eigene Prüfung (aus Farbanzahl, Ecken und Kantenstücken folgt je 4).

**i18n (DE/EN):** `move.faceWide.U…B` („obere zwei Schichten“ / “top two layers” …), `wing.<EDGE><1|2>` („oben-rechts, Teil 1“ / “top-right, part 1”), `error.duplicateEdge4`, `msg.validNoSolver` („Gültiger Würfel – der 4x4-Solver folgt.“ / “Valid cube – the 4x4 solver is coming soon.”). `formatParseError`: für `edgeImpossible` auf dem 4x4 `wing.*` statt `edge.*` (Erkennung an Positionsname mit Ziffer).

**Acceptance Criteria:**
- Gelöst: `parse4(solvedFacelets())` ok und `isSolved4`; Gelb oben / Blau vorne gehalten → gelöst.
- Round-Trip `toFacelets4(parse4(f).state, scheme) == f` für 50 Engine-Mischungen (40 Züge aus 36).
- Für 200 Engine-Folgen ist `parse4` ok (jede erreichbare Stellung ist gültig).
- Fehlerfälle: ein Feld leer; Farbe 15×; Ecke verdreht (3 Felder rotiert); Ecke gespiegelt (2 Felder getauscht → `cornerOrder`); Kantenstück-Felder getauscht → `duplicateEdge` mit Spiegel-Hinweis (DE/EN); unmögliches Kantenstück (Gegenfarben, Zählung ausgeglichen) → `edgeImpossible` mit „Teil 1/2“.
- Mischen: Länge 40, nie zweimal dieselbe Seite, nie `X, Gegenseite, X`.
- `puzzles.test.js` umfasst `'4x4'` (Schnittstelle, Mischung gültig, kein `solve`).

- [ ] Tests → FAIL → implementieren → PASS → Commit `feat: 4x4 model, validation and scramble`
