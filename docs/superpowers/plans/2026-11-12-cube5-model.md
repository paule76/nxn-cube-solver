# E1: 5x5-Modell und Darstellung – Implementation Plan

> Inline-Umsetzung auf `feature/cube5-model`; git-Historie ist die Aufzeichnung. Kein Merge nach `main` vor E2.

**Spec:** `docs/superpowers/specs/2026-11-12-cube5-model-design.md`

## Global Constraints
- Keine Abhängigkeiten, kein Build; Texte DE + EN; alle bisherigen Unit- und e2e-Tests grün.
- Feld-Reihenfolge U R F D L B, je 25 Felder; Engine `createMoveSet(5)`, Züge `movesFor(5)` (36).

### Task 1: Modell `src/puzzles/cube5.js` + Registry
**Files:** Create `src/puzzles/cube5.js`, `test/cube5.test.js`; Modify `src/puzzles/cube3.js` (export `centersOk`,
`findPiece`, `inversions`), `src/puzzles/index.js`, `src/i18n.js` (`error.centerCount`, `centerKind.x|t`,
`msg.validNoSolver` mit `{size}`), `src/messages.js` (`kind` übersetzen).

**Interfaces:** `CORNER_FACELETS5`, `MIDGE_FACELETS`, `WING_FACELETS5`, `WING_NAMES5`, `X_CENTER_FACELETS`,
`T_CENTER_FACELETS`, `SOLVED5`, `toFacelets5(state, scheme)`, `parse5(f) -> {ok, state, scheme}|{ok:false, code, params}`,
`isSolved5(state)`, `cube5` (Puzzle-Modul, `scramble` = 60 Züge).
- Ecken: 2x2-Eckfelder auf n = 5 skaliert (wie cube4). Mittelkanten: 3x3-Kantenfelder auf n = 5 skaliert.
- Kantenstücke: Aufkleber mit zwei Außenkoordinaten und freier Koordinate ≠ 0; Lesereihenfolge (n1×n2)·p > 0; Namen wie 4x4 (`UR1`/`UR2`).
- x-Mitten: eine Außenkoordinate, beide anderen ≠ 0; t-Mitten: genau eine der anderen = 0.

**Acceptance Criteria:**
- Für alle 36 Züge und 200 Zufallsfolgen: `toFacelets5(parse5(f).state, scheme)` == f (Modell == Engine).
- Gelöst in anderer Haltung → gelöst; die 6 festen Mitten bleiben bei allen Zügen stehen.
- Je ein Test pro Fehlercode inkl. `centerCount` (x- und t-Mitte derselben Farbe vertauscht) mit DE/EN-Text.
- Mischen: Länge 60, keine gleiche Seite zweimal, kein „X, Gegenseite, X“.

- [ ] Tests → FAIL → implementieren → PASS → Commit `feat: 5x5 model`
